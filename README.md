# ピッチの辞書（Web版）

サッカー用語118語を「動く戦術ボード」で3秒図解する用語図鑑。
公開URL: https://pitch.kokokikaku.com/ ／ 配信: GitHub Pages（`main` ブランチのファイルをそのまま配信）

## URL設計（日英）

| | 日本語 | 英語 |
|---|---|---|
| トップ | `/`（SPA本体） | `/en/` |
| 用語一覧 | `/terms/` | `/en/terms/` |
| 用語ページ | `/terms/<id>/` | `/en/terms/<id>/` |

同じ用語IDを日英で共有し、`hreflang` で相互に `alternate` 指定している。`x-default` は英語（日本語でも英語でもない利用者には英語のほうが読めるため。2026-09-25 に日本語から変更）。
トップ（`index.html`）にも同じ3行を手で書いてある。片側だけの指定は Google に無視されるので、消さないこと。
トップは日本語以外のブラウザで初めて来た人に「Read it in English」の案内を出すが、**自動では英語に切り替えない**（Googlebot は英語環境で描画するため、自動切替にすると日本語トップが英語として登録される）。

英語ページの共有画像は `og-en.png`（日本語ページは `og-v2.png`）。作り直すときは `scripts/og-en.html` をChrome のヘッドレスで 1200×630 に撮る。共有ボタンは日本語ページが X・LINE、英語ページが X・WhatsApp・Reddit。

トップの英語表示（`/?lang=en`、英語ページの「Open the interactive version」から来る）では、`applyLang` が
タイトル・共有ボタン（`/en/` を英語で共有し LINE は隠す）・フッターを英語にし、日本語の説明ブロック（`.seoblock`）と
日本向けのアフィリエイト枠を隠す。用語モーダルの「詳しいページ」も `/en/terms/<id>/` へ飛ぶ。

Google アナリティクスは、EEA・英国・スイスからのアクセスで解析・広告の Cookie を既定で使わない
（`gtag('consent','default',…,region)`。`index.html` と `build-pages.js` の両方に書いてある）。
同意バナーを置くか AdSense が承認されたら、ここを見直すこと。プライバシーポリシーの英語部分は `/privacy.html#en`。
英訳は118語すべてに存在し（`TR_EN`）、**戦術ボード内のキャプションも `VIZ_TXT` で英語に差し替わる**。
日本語ページには英語版へのリンクだけを置き、英文の本文は載せていない（重複コンテンツを避けるため）。

## ★ index.html を編集したら必ず実行する

用語の追加・修正、戦術ボードの変更、CSPの変更など **`index.html` に手を入れたら必ず** これを実行してからコミットする。
静的ページ・CSS・サイトマップ・トップページ内の内部リンク一覧がまとめて作り直される。

```
node scripts/build-pages.js
```

やっていること:

1. `index.html` のメインスクリプトを Node の `vm` 上で実行し、`TERMS` / `CAT` / `VIZ` / `TR_EN` / `trViz` を取り出す
2. 日英それぞれで用語ページを書き出す（戦術ボードのSVGはビルド時に文字列として展開＝JS不要で表示される）
3. 英語ページを書くときは `lang` を `"en"` にしてから `trViz()` を通し、ボード内のキャプションも英訳する
4. 戦術ボードのCSS・アニメーションを `index.html` から抜き出して `terms.css` に入れる
5. `sitemap.xml` を作り直す（日英241URL）
6. `index.html` 内の `<div id="seolinklist">` に全用語ページへのリンクを埋め込む

英訳が1語でも欠けているとビルドは**エラーで止まる**。用語を追加したら `TR_EN` にも必ず追加すること。

> ⚠️ 生成物もコミットする。GitHub Pages はビルドを行わず、リポジトリのファイルをそのまま配信するため。

## アフィリエイト広告の設定

`affiliates.js` の `items` を編集するだけで、トップ・用語モーダル・用語ページ・一覧ページの広告枠が切り替わる。
HTMLの再生成は不要。`enabled:false` の項目や未入力の項目は自動で非表示になり、枠ごと消える。
書き方・注意点はファイル冒頭のコメントに書いてある。

- 広告リンクには自動で `rel="nofollow sponsored noopener"` と「PR」表記が付く（景品表示法のステマ規制対応）
- 外部ドメインの画像を使う広告は、`index.html` の CSP（`img-src`）にドメインの追加が必要な場合がある
- `<script>` を含む広告素材（A8のウィジェット等）はCSPで動かない。script不要の素材を選ぶこと
- **`langs` を省略した項目は日本語ページにしか出ない。** 英語ページ(`/en/`)は世界中から読まれるので、
  日本国内限定のサービス（WOWOW・スカパー！・楽天など）を出しても成約せず体験も損なう。
  現状、英語ページのアフィリエイト枠は空で非表示になる（AdSenseの自動広告だけが出る）。
  海外からでも申し込める広告主と提携できたら、その項目に `langs: ["ja", "en"]` を足す。

## ★ Service Worker のキャッシュ戦略（触るときの注意）

`sw.js` は用途ごとに戦略を変えている。

| 種類 | 戦略 | 理由 |
|---|---|---|
| HTML | network-first | 更新を確実に届ける |
| JS / CSS / JSON / XML | stale-while-revalidate | 表示は即座、裏で取り直して次回に反映 |
| 画像・フォント | cache-first | めったに変わらない |

2026-09-04 に、広告設定を直しても本番に反映されない事故が起きた。原因は3つ重なっていて、
どれか1つでも欠けると同じことが再発する。`sw.js` を触るときは3つとも守ること。

1. **JS・CSSを cache-first にしない。** `affiliates.js` を cache-first で持っていたため、
   一度でも訪れた人には永久に古いファイルが配信された。ページ側から
   `fetch(url, {cache:'no-store'})` してもService Workerに横取りされて効かない。
2. **裏での再取得は必ず `event.waitUntil()` に渡す。** `respondWith` がキャッシュで即座に
   解決すると、ブラウザはSWを終了してよいと判断し、`fetch` と `cache.put` が完了前に
   打ち切られる。`waitUntil` はイベントハンドラ内で**同期的に**呼ぶこと
   （`.then` の中から呼ぶと `InvalidStateError`）。
3. **再取得の `fetch` には `cache:"no-cache"` を付ける。** GitHub Pages は静的ファイルに
   `Cache-Control: max-age=600` を返す。素の `fetch` はブラウザHTTPキャッシュを経由するので、
   SWは「取り直したつもりで10分前の応答」をキャッシュに書き戻してしまう。
   実際にキャッシュ側8745バイト／配信側8861バイトのズレが残り続けた。

`ASSETS` に載せるファイルを増減したときは `CACHE` のバージョン文字列を上げること。

## iOSアプリ版との関係

iOSアプリ（別リポジトリ `pitch-app`）は `scripts/build-data.js` でこの `index.html` から
用語データと戦術ボードHTMLを抽出している。`TERMS` / `VIZ` / `CAT` / `EMOJI` / `TR_EN` / `I18N` / `TREND` の
**変数名と構造を変えるとアプリ側のビルドが壊れる**ので注意する。

日本語ページ（`index.html` と `terms/` 配下）には、iPhone の Safari でアプリを案内する
`<meta name="apple-itunes-app">` を入れてある（`build-pages.js` の `APP_BANNER`）。
アプリは日本の App Store でしか配信していないので、英語ページには入れない。配信国を広げたら英語ページにも足す。
